# Proposal: S8c — Dashboard de Alertas (SystemAlert)

## Intent

SystemAlert notifications (`category: 'system'`) are dispatched by the backend (e.g., heartbeat timeout, subsystem failures) but landlord admins have no interface to view, filter, or acknowledge them. This builds a dedicated alerts dashboard so admins can monitor system health and act on critical conditions before they escalate.

## Scope

### In Scope
- `AlertController` with `index()` (paginated, filterable) and `read()` (mark as read)
- Route `GET /admin/alerts` and `POST /admin/alerts/{notification}/read`
- `landlord/alerts.tsx` page — severity filters (critical/warning/info), unread/all toggle, date range, mark-as-read
- Fix `HandleInertiaRequests::resolveUnreadNotificationsCount()` to include `Landlord` instances
- Badge in admin sidebar nav showing unread alert count
- Feature + unit tests

### Out of Scope
- Reconciliation dashboard KPIs (S8f)
- Payment notification monitoring (S8e)
- Manual notification compose (exists at `/admin/notifications`)
- Android device management or heartbeat history

## Capabilities

### New Capabilities
- `alert-dashboard`: Browse, filter (severity, read/unread, date range), and acknowledge system alerts generated by the platform's background processes. Queries the landlord `notifications` table filtering `data->>'category' = 'system'`.

### Modified Capabilities
None — no existing capability changes at spec level

## Approach

1. **Prerequisite**: Fix `HandleInertiaRequests::resolveUnreadNotificationsCount()` — change `$user instanceof User` to `$user instanceof User || $user instanceof Landlord` so the existing `unread_notifications_count` shared prop works for admins
2. **Controller**: `AlertController@index` queries Landlord's notifications with `where('data->>category', 'system')`, paginates, accepts severity/read_at/date query params. `@read` calls `$notification->markAsRead()`
3. **Route**: `GET /admin/alerts` → `landlord.alerts.index`, `POST /admin/alerts/{notification}/read` → `landlord.alerts.read` (inside existing `prefix('admin')` group)
4. **Page**: Single file `landlord/alerts.tsx` — server-side filter params passed via Inertia visit, table with severity badge, timestamp, message, mark-as-read button
5. **Admin sidebar**: Add "Alertas" `NavItem` to `mainNavItems` in `AppSidebar` (admin branch) with `Bell` icon; render badge using `unread_notifications_count` (unread system + regular notifications count)
6. **Tests**: `AlertControllerTest` (feature) — index returns paginated alerts, filters by severity, read marks notification read, edge cases (empty DB, no system alerts)

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| `unread_notifications_count` mixes system + all notifications | High | Acceptable for v1; doc comment explains scope |
| Large notifications table | Low | Paginate 20 per page, filter by category index |
| PostgreSQL JSON index missing | Low | Add composite index on `(notifiable_type, data->>'category', read_at)` if perf degrades |

## Rollback Plan

Revert `HandleInertiaRequests.php` Landlord instanceof guard. Remove routes from `landlord.php`. Delete controller and page file. No schema rollback needed.

## Dependencies
